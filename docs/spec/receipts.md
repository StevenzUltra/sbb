# Receipts, message ids and the envelope

## Message id

32 lowercase hex (`crypto.randomBytes(16)`), generated by the sender. Printed short as the
first 8 characters. The same id is used for the Claude `msg_id` frame field, for the
receipt file, and for `sbb reply <id>`.

## Receipt object

See `Receipt` in `src/types.js`. Exactly one of four statuses:

| status       | when                                                                       | required fields     |
| ------------ | -------------------------------------------------------------------------- | ------------------- |
| `delivered`  | protocol receipt `delivered`, or the screen confirmed submission           | `via`, `elapsedMs`  |
| `queued`     | target busy and the message sits in its queue (Claude priority queue, Cursor follow-up, codex queue without an observed turn) | `via` |
| `unverified` | typed, could not confirm; one Enter retry already spent                    | `reason`            |
| `blocked`    | nothing was sent                                                           | `reason`            |

Reason vocabulary (extend only by adding to this table):

`pane_in_copy_mode`, `target_busy`, `target_prompting`, `foreground_program`,
`enter_swallowed_twice`, `held`, `denied`, `refused`, `dropped`, `expired`,
`transport_unavailable`, `socket_connect_failed`, `auth_rejected`, `no_rollout`,
`thread_not_found`, `target_not_found`, `target_ambiguous`, `policy`, `no_transport`.

## Receipt log

Every send appends one JSON line to `~/.sbb/log/receipts.jsonl`:

```
{"t":1788881135650,"msgId":"...","from":"lead","to":"ios","address":"ios","status":"delivered","via":"uds","elapsedMs":312,"reason":null,"textPreview":"[lead@a/claude:24:8.1][主脑] 复核 PR ..."}
```

`sbb watch` tails this file plus the inbox events. `sbb collect` reads
`~/.sbb/inbox/<brain>/*.json` (one file per received reply, written by the inbox server or by
`sbb reply` when the target is the user).

## Envelope

One line, generated by SBB:

```
[<sender>@<account>/<cli>:<coord>][<role>] <body>   (sbb:<msgId8>)
```

- `<sender>` = brain name, or the CLI name when the sender is not a registered brain
  (`Claude`, `Codex`, `Gemini`, `Cursor`), matching the existing cross-ai-tmux-bridge skill
  so unregistered sessions still understand it.
- `<role>` = `主脑`, `子脑`, `用户`, or the role passed with `--role`.
- The `(sbb:<id>)` suffix lets the receiver answer with `sbb reply <id> ...` without knowing
  the sender's coordinates.
- The body is one line. `sbb tell --file <path>` sends "见 <path>" plus the first line of
  the file instead of the content.

## CLI output

Human form (default), one line:

```
delivered  msg=2522afe4  via=uds  0.3s
blocked    msg=9c01d2aa  via=send-keys  reason=pane_in_copy_mode
```

`--json` prints the Receipt object. Exit codes: 0 delivered/queued, 3 unverified, 4 blocked,
2 usage error, 1 internal error.
