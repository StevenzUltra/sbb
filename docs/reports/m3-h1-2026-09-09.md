## 点验发现并修复的真实缺陷

1. `controlClient.on('data')` 监听在子进程对象而非 `child.stdout`，导致 `%output` 全部丢失：
   只收到初始屏、实时输出为零。原始控制客户端探针可收到 `%output`，修复后 live 帧到达；
   `test/host.test.js` 增加回归断言。
2. `resize-pane` 对 detached 会话中窗口唯一窗格是空操作（实测 200x49 保持 200x49，tmux 3.7c）。
   `resizePane` 对单窗格窗口追加 `resize-window`，签名不变。
3. `sbb ui --no-open` 被严格 `parseArgs` 拒绝（`Unknown option`）。`util.parse` 增加可选第三参数
   `allowNegative`；新增 `test/ui-cli.test.js`。

## 规范读数与差距（按 AGENTS「上报而非擅改签名」）

1. `docs/spec/ui-server.md:55` 只写 `resize-pane`；实测单窗格 detached 场景无效，故追加
   `resize-window`（见上，接口未变）。
2. `%session-changed`：attach 自身会报告当前会话，因此只在事件会话与订阅会话不同时关闭连接。
3. TPS 时长取「与上一条记录的间隔」，首个计数回合可能带真实间隔而非默认 1000ms。
4. `mergeConfig` 只保留固定字段，`terminal` 会被丢弃；`readTerminalPreference` 直接读原始
   `config.json` 以符合 spec:67 的字面要求，但 `sbb policy` 写回配置会抹掉手写的 `terminal` 键。
   是否把 `terminal` 纳入 `mergeConfig` 由 lead 决定（本轮未改共享配置模块）。
5. `/api/state`、`/api/events` 目前由 `server.js` 内的私有 watcher 提供，接口按 h3 的
   `snapshot()`/`watch()` 约定；`src/ui/data.js` 落地后替换。本 PR 未引入 stub。
6. 按最新 spec 已补 `receipts`（最近 500 条，最新在前），`test/ui-server.test.js` 覆盖。

## 追加（同日晚）：server.js 接入 src/ui/data.js（分支 m3/h1-ui-data）

派单：`995a5f34`。范围：`/api/state` 改用 `src/ui/data.js snapshot()`，事件改用 `watch()`，
删除 `server.js` 里的私有 watcher；对照 `docs/spec/ui-server.md` 逐一核对事件名；补测试。

### 改动

- `buildState` 调用 `snapshot({ sbbDir, readQuota, readConfig, listHeld, listPlans, listAllClaims,
  readReceipts, listBrains, accountList, allChannels, tps })`，保留测试注入点；服务器只补 data.js
  不拥有的东西：roster 实时状态、自己的 TPS 采样、展平的账号 x CLI 模型目录。
- 私有 watcher（`startWatcher`/`rescan`/`snapshotJson`/`watcherState` 测试缝、`node:fs watch`
  导入、`watchers` 数组、`RECEIPTS_LIMIT` 导出）全部删除，改为 `data.js watch()` 的九类事件映射。
- `emit({type,...})` 改为 `emitEvent(name, object)`：真正的 `event: <name>` + 原始对象负载；
  服务器自身错误改走 SSE 注释（`error` 是 EventSource 保留名，且控制台没有对应处理器）。
- `heartbeat` 从注释帧改为具名事件，每 15 s（`deps.heartbeatMs` 为测试缝）。

### 发现的集成缺口（未擅自改共享模块，按规则上报）

1. **SSE 事件此前根本到不了控制台**（本 PR 修复）：旧实现只写 `data: {"type":...}` 且带包裹层，
   而 `web/src/api/http.js` 用 `addEventListener` 订阅九个具名事件并直接 `JSON.parse(msg.data)`
   当对象用。实测修复后真实进程收到 `event: receipt`。
2. **data.js `watch()` 只监听启动时已存在的路径**：`log/` 若在 `sbb ui` 启动后才有，收据事件要等
   30 s 重快照。实测：启动时无 `log/` → 5 s 内无事件；`log/` 已存在 → 132 ms 到达。建议 h3 兜底监听
   父目录或在扫描时补挂新目录。
3. **data.js 的 TPS 探测落空**：`src/metrics/tps.js` 只导出 `createTps`，`snapshot().tps` 因此为 null；
   服务器保留自己的 5 s 采样并覆盖 `tps`（规范要求 5 s，data.js 重快照是 30 s）。建议 h3 接受注入的
   `tps` 读取器，或 metrics 暴露 `current()`。
4. **quota 行形状与控制台不一致**：服务器发 `usage_snapshot` 行，控制台读 `{key,label,pct,note}`
   （`web/src/components/TopBar.vue`），额度条因此为空。本轮未改（`pct` 是剩余还是已用需要产品口径）。
5. `accountList` 没有控制台默认 CLI 用到的 `clis` 字段（回落到第一个可用 CLI），影响很小。
