## 1. 挂死：根因是时长单位，不是传输

主脑的 `--timeout 6000` 被 `parseDuration` 当成 **6000 秒**（裸数字走"秒"分支），
而 `docs/spec/cli.md` 与 usage 写的是 `--timeout <ms>`。于是那次投递实际等了 **100 分钟**：
消息早就送达（h1 的回信 00:51:01 已落盘，证明事件循环活着），但传输在等一个正常投递
永远收不到的 `peer_message_status`，回执不落盘、不打印，`inboxCache` 里的收件箱继续监听
socket，进程自然不退。

修法（根因，不是加超时兜底）：

- `src/cli/util.js` `parseDuration`：裸数字按**毫秒**解析，`ms/s/m/h` 后缀照旧；`6000` 现在就是 6 秒。
- `src/cli/tell.js` / `ask.js` / `reply.js`：`finally` 里 `await inbox?.close?.()` 之后再调
  `closeInboxes()`，覆盖传输自己开的收件箱（原先这条路径从没有 CLI 命令关闭过）。
- `bin/sbb.js`：`exitNow(code)` 先 flush stdout/stderr 再按退出码 `process.exit`，避免管道下截断。

真机点验（主脑原命令形态，真实环境、真实对端 `b/claude:eagerstudy-e8`）：

```
$ node bin/sbb.js tell b/claude:eagerstudy-e8 --timeout 6000 "h3 自检：挂死修复验证，请忽略。"
```

回执已落 `~/.sbb/log/receipts.jsonl`：`status=delivered via=uds+screen elapsedMs=6013`。
管道不截断：`node bin/sbb.js ls | cat` 输出完整；未知目标 `tell nosuchtarget.h3` exit=4 且 stderr 完整。
