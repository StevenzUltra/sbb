## 规格偏差与需要主脑确认的点

1. **`registry.md` §1 的 Codex 进程推断是单层 `pgrep -P <pane_pid>`，实测无效**：真实链路是 pane shell → `zsh -l` → `node /opt/homebrew/bin/codex`，单层查不到 codex。已实现为有界进程树遍历（深度 4、进程数 64），并在 `roster.js` 注释里写明与规格的差异。建议把 §1 改成"进程树"措辞。
2. **未注册发送方的信封前缀**：`receipts.md` 写 `<name>#<id>`，未注册时按 CLI 显示名（`Claude`/`Codex`/`Gemini`/`Cursor`）；`registry.md` 的占位写作 `[<cli>@...]`。按 receipts.md 保留显示名（与既有 cross-ai-tmux-bridge 兼容）。
3. **`machineTag` 本机推导值为 `SSL`**（hostname `StevendeMac-Studio.local` → 词首 S/S/L）。若希望固定为 `SMS` 之类，请在 `~/.sbb/config.json` 写 `{"machineTag":"SMS"}`（代码已支持，未擅自写入用户主目录）。
4. **计数器回退保护**：分配时取 `max(counter, brains/_retired/回执日志的最大序号) + 1`，即使 counter 被手工改小也不会重发 id（比规格"仅丢失时兜底"更严，符合"只增不减"）。
5. **过期锁**：`O_EXCL` 锁超过 2 s 视为持有者已崩溃并清除，避免一次崩溃永久卡住分配。
6. **`doctor` 退出码**：重复 id/uuid 时打印 `brains DUPLICATE ...` 并 exit 1（原契约只以 tmux 可达性决定 0/1），无重复时行为不变。
7. **Codex 状态列**：`cli-profiles.js`（h2 任务）尚不存在，roster 通过动态 import 委托，缺失时 Codex/agy/cursor 状态显示 `?`，不猜 idle。h2 落地后自动生效。
8. **回执新增字段**：`fromId` / `toId`（有脑时），按 `receipts.md` 新增要求写入；信封、`ls` 首列、`adopt` 输出均带 id。
9. **`ls <id|name>` 查不到**（既无活 pane 也无记录）时 exit 4 并报错，不打印空行。
