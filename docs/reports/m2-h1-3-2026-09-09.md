# M2 h1 追加报告：CLI 作为 pane 命令，简报一律走文件

分支 `m2/h1-lifecycle-3`，base `origin/main` = `77bd0a0`（PR #13 已合入）。派单 msgId `5f4d6d59`。

## 问题

排练里 `sbb spawn` 在真实登录 zsh 下 `not_ready` 60s：把几千字节的简报当命令行用 `send-keys` 打进交互 shell，zsh 的自动补全 / 高亮 / bracketed-paste 逐字符处理，60 秒内命令都没打完，屏幕上还停着半行 `exec env … --append-system-prompt $'…'`。

## 改动

| 文件 | 内容 |
| --- | --- |
| `src/lifecycle/launch.js` | `prepareBrief` 一律写 `<sbbDir>/briefs/<id>.md`（不再有「短简报内联」分支，`BRIEF_FILE_LIMIT` 删除）。`buildCommand` 改为 `briefFile` 入参，返回新增 `paneCommand = ['sh', '-c', shellLine]`；claude 用 `--append-system-prompt-file <file>`，codex / agy / cursor 用 `"$(cat <file>)"` 作为 prompt 参数（由 shell 展开，不经交互提示符） |
| `src/lifecycle/spawn.js` | `new-window` / `split-window` 直接带上 `command.paneCommand`，CLI 就是 pane 的命令；删除 `sendLiteral` + `sendKey`。pane 选项照旧 `set-option`。失败路径仍 `kill-pane` |

`claude --append-system-prompt-file` 实测存在：`claude --help` 列出 `--system-prompt[-file]` / `--append-system-prompt[-file]`，且 2.1.263 二进制里出现 11 次。

### 真实点验（scratch `tmux -L sbb-h1`，`default-shell /bin/zsh` 未改；`SBB_DIR=/tmp/sbb-h1-acc3`，账户 a）

1. claude + 20KB 简报（`--brief-file`）：

```
$ time sbb spawn --name claude-long --role main --account a --cli claude --cwd /Users/steven/developer/eagerstudy --brief-file /tmp/sbb-h1-acc3/brief.md
spawned SSL-0001 claude-long acc:2.1
brief     /tmp/sbb-h1-acc3/briefs/SSL-0001.md
1.241 total   exit=0
```

同一场景改动前 60s 超时。pane 的命令是 CLI 本身：

```
$ tmux -L sbb-h1 list-panes -a -F '#{window_name} #{pane_id} cmd=#{pane_current_command}'
scratch %0 cmd=zsh
ai-a    %1 cmd=2.1.263
$ ps -o command= -p $(tmux -L sbb-h1 display-message -p -t %1 '#{pane_pid}')
claude --append-system-prompt-file /tmp/sbb-h1-acc3/briefs/SSL-0001.md
```

pane 首屏是 Claude Code 启动横幅，没有半行 `exec env`。

2. codex（`$(cat …)` 展开）：

```
$ time sbb spawn --name codex-long --role main --account a --cli codex --cwd /private/tmp --brief-file /tmp/sbb-h1-acc3/brief.md

1.224 total   exit=0

node /opt/homebrew/bin/codex 你是 long-brief 主脑。\012背景：这是一个很长的简报，用来验证多千字节文本不再经过 shell。…

3. 失败清理（未信任目录触发 claude 信任提示，60s 就绪超时）：

```

exit=4
$ tmux -L sbb-h1 list-panes -a -F '#{window_name} #{pane_id}'
scratch %0

失败的 pane 确实被 `kill-pane` 收走，没有残留（派单里观察到的「失败后 pane 还留着」在本次点验中未复现）。

4. 两个脑各自 `sbb kill … --yes` 成功（claude `exited after /exit`，codex `pane was not idle; kill-pane`）。

清理：`tmux -L sbb-h1 kill-server`、`rm -rf /tmp/sbb-h1-acc3`。
