## env 变量证据

| CLI | 目录 | 导出的 env | 依据 |
| --- | --- | --- | --- |
| claude | `<base>/claude` | `CLAUDE_CONFIG_DIR` | sbb 既有实现 |
| codex | `<base>/codex` | `CODEX_HOME` | sbb 既有实现 |
| agy | `<base>/gemini` | 无 | 本机没有可查证的 per-account 配置变量，只建目录不猜变量 |
| cursor | `<base>/cursor-agent` | `CURSOR_CONFIG_DIR` + `CURSOR_DATA_DIR` | 用户自己的 `~/bin/ai-a` 两个变量指向同一目录 |
| kimi | `<base>/kimi` | `KIMI_CODE_HOME` | `~/bin/ai-a` 与二进制内字符串 |
| grok | `<base>/grok` | `GROK_HOME` | `~/bin/ai-a` |

`~/bin/ai-a` 里的 `CURSOR_USER_DATA_DIR`（`$BASE/cursor`，Cursor IDE GUI 状态）刻意不建模、不导出。

## 登录判定（`account ls` 的 yes/no）

- 凭据文件标记（如 `claude/.credentials.json`、`codex/auth.json`）任一存在即为 yes。
- keychain 登录不落凭据文件，因此再看会话/配置标记（如 `.claude.json`、`sessions`、`cursor/cli-config.json`、`kimi/oauth`）；目录型标记必须非空。
- codex 的 `config.toml` 被排除，因为生成的 wrapper 自己会写它，否则空账户会被误判为已登录。
- 全程不读取凭据内容，只看路径存在性。

## catalog 规则

某账户存在该 CLI 的配置目录时，`catalog()` 才在该账户下列出该 CLI；agy/cursor 的 `source` 串写明所用配置目录。kimi/grok 仍不在 `CATALOG_CLIS`（h1 范围），因此暂不出现在 `sbb catalog`。

## 真实点验

scratch HOME 下 `sbb account add zz`（`HOME=$H`）：

```
~/.ai-account-zz/{claude,codex,cursor-agent,gemini,grok,kimi}   全部 drwx------
~/bin/ai-zz                                                     -rwx------
```

wrapper `env` 输出六个变量：

```
export CODEX_HOME="…/.ai-account-zz/codex"
export CLAUDE_CONFIG_DIR="…/.ai-account-zz/claude"
export CURSOR_CONFIG_DIR="…/.ai-account-zz/cursor-agent"
export CURSOR_DATA_DIR="…/.ai-account-zz/cursor-agent"
export KIMI_CODE_HOME="…/.ai-account-zz/kimi"
export GROK_HOME="…/.ai-account-zz/grok"
```

本机 `sbb account ls`：9 列表头，`a` 行为 `yes yes no yes no yes - /Users/steven/bin/ai-a`（AGY=no 是空目录无会话标记，KIMI=no 同）。

本机 `sbb catalog --json` 的账户/CLI 组合：

```
default: claude, codex, agy, cursor
a:       claude, codex, agy, cursor
b:       claude, codex
c:       claude, codex
```
