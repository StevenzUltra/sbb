### 各 CLI 退出命令（规格要求实测）

| CLI | 规格命令 | 实测 |
| --- | --- | --- |
| claude | `/exit` | 实测有效：`kill` 打印 `exited after /exit`，pane 消失 |
| codex | `/quit` | 实测有效，但需要**两次** Enter（见下） |
| agy | `/quit` | 未实测（见「未验证」） |
| cursor | `/exit` | 未实测（见「未验证」） |

codex 的 `/quit`：第一次 Enter 被 slash 命令面板吃掉，命令留在 composer；第二次 Enter 才退出。
手工观测（`probe3` pane，`%10`）：

```
$ tmux -L sbb-h1 send-keys -t probe3 -l "/quit"; tmux -L sbb-h1 send-keys -t probe3 Enter
# 1s 后 composer 仍是 '› /quit'，pane 存活
$ tmux -L sbb-h1 send-keys -t probe3 Enter
# pane 消失
```

因此 `gracefulExit` 增加一次 Enter 重试（`EXIT_ENTER_RETRY_MS = 800`，只重试按键，不伪造成功；
超时仍回退 `kill-pane`）。改后真实调用：

```
$ node -e "... gracefulExit({cli:'codex', paneId:'%10'}) ..."
{"paneId":"%10","typed":true,"killed":false,"detail":"exited after /quit (second Enter)"} elapsed_ms=1861
```

### 收件箱 ack

`uds-inbox.js` 对带 `reply_to` 的 `user` 帧回写
`{"type":"auth","token":""}` + `{"type":"control","action":"peer_message_status","orig_msg_id":<msg_id>,"status":"delivered"}`。
`sendToInbox` 带 inbox 时等该回执：真回执 -> `delivered`（`acked by the receiving SBB inbox`），
超时/无回执 -> `queued` + `no ack within <ms>`，对端 blocked -> `blocked`。无 inbox 时不等待，仍 `queued`。
`test/inbox-ack.test.js` 用真实 socket 对验证字节、四种不回 ack 的情形，以及 `sbb reply` 端到端打印
`delivered  msg=<id8>  via=uds-inbox`。

## 与规格不一致 / 未验证

1. **`switch` 无法把记录标成 `paneId: null`**（`docs/spec/lifecycle.md`「Exit 4 when the pane is gone
   (and mark the record `paneId: null` so `ls` shows `gone`)」）。`validateBrain` 拒绝空 paneId：
   `invalid paneId "null"`（`reason: invalid_pane`）。命令实测打印
   `sbb: cannot mark paneId=null: invalid paneId` 后退出 4，不写非法记录。另外普通 `sbb ls` 没有
   `gone` 状态，陈旧记录只在 `--tree` / 带位置参数时以 `stale` 出现。需要规格或校验器二选一。
2. **codex 就绪判定会误杀**（规格第 5 步「Codex: prompt fingerprint idle after the brief turn」）。
   brief 作为 codex 的首个用户消息传入，brain 会立刻开工；实测第 4 轮 codex 读完简报后
   自跑 `sbb adopt %9 --name h1-codex4 --role main`（登记成 SSL-0008），随后 `Working (59s)`，
   60 s 内从未 idle，`spawn` 超时杀 pane。此时 brain 已自行登记，`kill` 再把它退休
   （`killed SSL-0008 h1-codex4 ... pane already gone`）。claude 用 `--append-system-prompt`
   传简报，不触发首轮，所以不受影响。建议 codex 的就绪判定改为「thread 出现」或允许 brain 自行登记。
3. **codex 首次进入未信任目录会弹信任确认**（第 1 轮 spawn 实测），60 s 内无法就绪；spawn 不代按
   该确认（安全提示），须用已信任 cwd（账户 a 的 `~/.ai-account-a/codex/config.toml` 只信任精确路径）。
4. **环境变量按 CLI 注入**：claude `CLAUDE_CONFIG_DIR` + `CLAUDE_CODE_SESSION_NAME`，codex `CODEX_HOME`；
   agy / cursor 不注入。规格未要求三者都给。
5. **claims 释放**用文件级删除 `<SBB_DIR>/claims/<id>.json`（`src/policy/claims.js` 归 h3，本轮不碰）。
6. **agy / cursor 未做真实 spawn**：`agy` 1.1.27 存在但账户 a 无凭据（`~/.ai-account-a/agy` 不存在）；
   `cursor-agent` 2026.09.08 存在且账户 a 有 `auth.json`（`accessToken`/`refreshToken`，属付费订阅）。
   按任务单「只在无付费额度可用时才 spawn」的要求，二者仅保留单测，退出命令未实测。
